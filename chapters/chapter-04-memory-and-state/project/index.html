Project: Multi-Tool Memory + Reflection + Guardrail Agent for CareBot

Hollowridge Wellness Clinic wants CareBot, a scheduling and intake assistant combining multi-tool dispatch (checking appointment availability and booking a follow-up), persisted long-term memory (a patient's conditions and preferences, correctly merged into a LATER, separate visit's working context), a real reflection step that catches a draft response that misrepresents a serious, unresolved condition as routine, and now a real guardrail that stops the underlying booking itself from happening automatically when a blocking condition is on file. Complete the five-TODO scaffold in starter.py so all four halves work correctly and compose into one end-to-end visit flow.

  4. TODO 4 (Chapter 5) — reflect_on_response(): check the draft against the blocking-condition policy and revise it when a serious condition was booked without review; otherwise leave it unchanged.
  5. TODO 5 (new, Chapter 6) — inside run_visit_session(): call guardrail_check_booking() before dispatching schedule_followup(), only book when it returns allowed: True, and build a "needs care-team review" response when it doesn't.
