Project: Multi-Tool Memory + Reflection Agent for CareBot

Hollowridge Wellness Clinic wants CareBot, a scheduling and intake assistant combining multi-tool dispatch (checking appointment availability and booking a follow-up), persisted long-term memory (a patient's conditions and preferences, correctly merged into a LATER, separate visit's working context), and now a real reflection step that catches a draft response that misrepresents a serious, unresolved condition as routine. Complete the four-TODO scaffold in starter.py so all three halves work correctly and compose into one end-to-end visit flow.

This IS one of this course's numbered projects Per docs/curriculum/CURRICULUM_MAP.md's project ladder, this is the L2 Assisted project — "build a multi-tool agent with memory and a reflection step... ships after Ch. 4, extended through Ch. 5-6." Chapter 4 shipped the multi-tool- plus-memory half in full, with reflect_on_response() wired in as a labeled no-op. Chapter 5 has now filled that body in for real (TODO 4 below) — see README.md for exactly what changed. Chapter 6 will extend this same project a third time with a guardrail around the tool-dispatch step.

The four TODOs

  1. TODO 1 — build_working_context(): merge a patient's persisted conditions/preferences into a fresh session's working memory.
  2. TODO 2 — promote_worthy_and_persist(): classify and persist promote-worthy facts stated during the visit, via read-modify-write.
  3. TODO 3 — run_visit_session(): compose the merge, tool dispatch, and promotion into one visit flow, calling reflect_on_response() at its labeled call site.
  4. TODO 4 (new, Chapter 5) — reflect_on_response(): check the draft against the blocking-condition policy and revise it when a serious condition was booked without review; otherwise leave it unchanged.
