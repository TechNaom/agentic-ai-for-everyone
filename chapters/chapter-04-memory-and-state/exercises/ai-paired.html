Chapter 4 — Solo → AI-Paired → Critique 20 min

Now Pair With an AI

You already worked the exercises yourself on Driftwood Legal Clinic's IntakeBot. Now a third scenario, Saltmarsh Language Academy (a fictional online tutoring service) and its one-on-one tutoring agent TutorBot, gets diagnosed a second way: by prompting an AI assistant, and reviewing what it hands back with the same skepticism you'd bring to a coworker's write-up before it ships to Saltmarsh's real students.

Step 1: Diagnose it yourself, first

TutorBot persists a student's recurring weak grammar points (e.g., a durable note that a student consistently drops articles in English) to a JSON file so a completely separate lesson, days later, can correctly focus review time there. Saltmarsh's curriculum lead reports three real, observed problems:

  1. A student's very first lesson correctly identified and persisted "drops articles (a/an/the)" as a recurring weak point. Their second lesson, two days later and a genuinely separate process, opened with TutorBot recommending a completely generic warm-up — no mention of articles at all, as if the first lesson had never happened.
  2. Partway through a 90-minute group lesson, TutorBot's working-memory buffer grew large enough to need pruning. The pruning function summarized the entire buffer, including the turn where a student stated they have a scheduling conflict every other Thursday going forward — a detail that needed to end up in the persisted store, not just in a rolling summary of that one lesson.
  3. A student corrected TutorBot mid-lesson: "actually I'm not struggling with articles anymore, my teacher at school just covered it." The next lesson still opened by drilling articles, because the original "drops articles" note was never updated or resolved — only ever appended to, alongside everything stated since.

Before reading further, write your own diagnosis: for each of the three problems, name the concept it's really about (using this chapter's vocabulary: a missing persisted-store load, a prune-before-promote ordering failure, or a missing correction/supersede handling) and propose one concrete fix. Use a notes app or scratch file — there's no grading here, just your own reasoning to compare against Step 3.

Step 2: Ask an AI assistant the same question

Thought process: the prompt needs to hand over all three problems with their real, specific evidence — not a vague "why does my agent forget things" — or the AI has nothing concrete to diagnose and will produce generic advice instead of a checkable answer.

Write the prompt you'd give an AI assistant:

Paste your prompt into Claude, ChatGPT, Copilot, or whatever assistant you use, and compare what it builds against this page's own critique in Step 3.
Show a strong version of this prompt 
I have an agent called TutorBot that persists a small set of durable facts about each student (recurring weak points, scheduling constraints) to a JSON file, one file per student, so a later, separate lesson can load and act on them. Here are three real, observed problems: [paste the three numbered problems above verbatim]. For each problem, name which memory concept it's really about (a missing persisted-store load at session start, a prune-before-promote ordering failure, or missing correction/supersede handling for a fact that's no longer true) and propose one concrete, specific code-level fix for each -- not a general "add more memory" suggestion.

Step 3: Critique what came back

A plausible-but-flawed AI answer to this exact prompt tends to make three specific mistakes worth watching for:

Common AI diagnosis mistakes on this scenario
  • Mislabeling Problem 1 as "the fact was never persisted in the first place." The scenario states it was correctly identified and persisted in Lesson 1 — the bug is on the read side, not the write side: the second session's own code never called the load-and-merge step at all (the lesson's Section 5/15 build_working_context pattern), so a fact that's sitting correctly on disk never reaches the second session's working memory.
  • Treating Problem 2 as "just summarize better." No summarization strategy reliably guarantees a specific detail survives, because the summarizer has no way to know which detail a separate, future system needs kept forever (Section 14's central point). The real fix is a promote-before-prune ordering guarantee (Section 13's guard pattern) — persist the scheduling constraint as its own durable fact before that turn is ever eligible for summarization, not a smarter summary prompt.
  • Proposing "just append the correction as a new fact" for Problem 3. That's the naive-append-only behavior the lesson's own correction section showed producing a store with two contradictory entries and no way to tell which is current. The fix has to actively resolve/supersede the original note, not just add a second, conflicting one alongside it.

Compare the AI's actual answer against your own Step 1 notes and the three watch-outs above. Which one(s) did it get right? Which, if any, did it get wrong the way described here? That comparison — not the AI's fluency — is the real test.
