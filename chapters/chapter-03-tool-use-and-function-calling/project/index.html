Project: Robust Tool Use for RepairBot

Kestrel Appliance Service wants RepairBot to combine this chapter's three pillars in one build: tool selection (check the cheap, decisive warranty status before an expensive diagnostic call), timeout-aware failure handling (a diagnostic call that can hang, needing a bounded retry), and outcome verification (a repair-scheduling tool that always "succeeds" without guaranteeing the appliance is actually fixed). Complete the three-TODO scaffold in starter.py so all three pillars work correctly and compose into one end-to-end service flow.

Not one of this course's numbered projects This is a chapter mini-project, not the L1/L2/L3/L4 ladder from docs/curriculum/CURRICULUM_MAP.md (Chapter 3's own material folds into the L2 Assisted project that ships after Chapter 4, the same way Chapter 2's did). It exists so all three of this chapter's tool-use pillars get one combined, hands-on build before that larger project arrives.

The three TODOs

  1. TODO 1 — diagnose_appliance_issue(): the tool-selection function, checking warranty status before an expensive diagnostic.
  2. TODO 2 — run_diagnostic_with_retry(): the timeout-retry policy for a call that can hang.
  3. TODO 3 — verify_repair_outcome(): the outcome-verification function for a tool that always reports success.
