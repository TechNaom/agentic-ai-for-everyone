Chapter 12 — Solo → AI-Paired → Critique 20 min

Now Pair With an AI

You already worked the exercises yourself on Lantern Hill Senior Living. Now a third scenario, Vantage Peak Ski Resorts (a fictional ski resort operator) gets an architecture decision built a second way: by prompting an AI assistant for a full Architecture Decision Record, and reviewing what it hands back with the same skepticism you'd bring to a coworker's design-review doc before approving a build.

Step 1: Design it yourself, first

Vantage Peak wants an agent for two request types: (1) lift-ticket refund requests when a lift is closed for weather, and (2) a 24/7 unattended avalanche-sensor alert that pages the ski patrol when a sensor trips. Before reading further, characterize this problem yourself: is it single- or multi-agent, and which specific fact decides it? Which of Chapters 4-11's mechanisms are load-bearing, and which aren't? What reliability/cost budget would you set for the avalanche-alert path versus the refund path? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same decision

Thought process: the prompt needs to force the AI to state problem FACTS before proposing a design, the same ordering this chapter's own framework uses -- otherwise a rushed AI answer tends to jump straight to "I'd use a multi-agent system" because the two request types sound different in tone, without ever checking whether they actually need independent concurrent actors (they don't -- both can be handled by one agent with the right tools and guardrails), and tends to either skip a guardrail on the irreversible refund action or skip the operating layer for the 24/7 unattended sensor path entirely.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
I need an Architecture Decision Record for an agent system at Vantage Peak Ski Resorts, handling (1) lift-ticket refund requests when a lift closes for weather, and (2) a 24/7 unattended avalanche-sensor alert that pages ski patrol when a sensor trips. Before proposing ANY design: state explicitly whether this needs a single agent or multiple agents, using this test -- multi-agent is only justified if there are distinct, specialized subtasks that can run INDEPENDENTLY, or if multiple actors must act CONCURRENTLY on shared state. Name the specific fact that decides it. Then, for each of: persisted memory, a grounded reflection step, a human-approval guardrail, reliability measurement, cost control, multi-agent dispatch, peer communication, and an operating layer (retries/timeouts/logging), state whether it's load-bearing for THIS problem and the one fact that makes it so or not. Then state a reliability/cost budget as two numbers (a minimum task-success rate and a maximum cost per run), with the avalanche-alert path getting the stricter of the two. Do not skip straight to a design before completing all three of these steps.

Step 3: Review it against this checklist

What a rushed AI-generated architecture decision tends to get wrong
  • Multi-agent chosen from tone, not facts. Does the AI justify splitting refunds and avalanche alerts into separate agents because they "feel different," without naming a concrete independently-runnable-subtask or concurrent-actor fact -- the exact over-engineering smell this chapter's Section 10 catches?
  • A missing guardrail on the refund action. Does the generated design actually gate the refund behind a human-approval checkpoint (Chapter 6), or does it quietly auto-approve every refund regardless of amount?
  • A missing operating layer on the 24/7 path. Does the design account for the avalanche-sensor path running UNATTENDED -- idempotent alert dispatch, a timeout on the sensor-read call, structured logging -- or does it only describe the conversational refund path and leave the sensor path as an afterthought?

Now compare the AI's ADR against this chapter's own lesson pattern (Sections 4-10, 17-19) and against solution.py in the exercises folder. Did it state facts before proposing mechanisms, or the other way around?
