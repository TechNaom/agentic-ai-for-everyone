Chapter 9 — Solo → AI-Paired → Critique 20 min

Now Pair With an AI

You already worked the exercises yourself on Hadleigh Civic Records Bureau's CaseScout. Now a third scenario, Corvindale Claims Network (a fictional multi-line insurance claims cooperative) and its supervisor agent ClaimScout, gets built a second way: by prompting an AI assistant for a supervisor/worker coordination layer, and reviewing what it hands back with the same skepticism you'd bring to a coworker's pull request before trusting its routing decisions.

Step 1: Design it yourself, first

ClaimScout dispatches incoming claims to three workers: AutoScout (auto claims), PropertyScout (property/home claims), and HealthScout (health claims). Before reading further, sketch your own plan: how would you route an ambiguous claim (e.g., "a tree fell on my car during the storm" touches both property and auto)? How would you verify a worker's result actually matches the claim it was given, and what would you do if the same claim got dispatched twice due to a retry? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same thing

Thought process: the prompt needs to state explicitly that an ambiguous or unroutable claim must NOT be dispatched to a best-guess worker (fail-closed routing), that each worker's result must be verified against the claim's own fields (not just checked for a well-formed shape), and that a retry must be idempotent -- otherwise a rushed AI answer tends to produce a router that always returns SOME worker even when uncertain, and a retry loop with no duplicate-dispatch protection, exactly the two failure modes this chapter's own Sections 6 and 13 demonstrated live.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
Write Python stdlib-only supervisor/worker coordination code for ClaimScout, a supervisor that dispatches insurance claims to three workers: autoscout (auto claims), propertyscout (property claims), healthscout (health claims). I need: (1) a keyword-based router that scores each worker against a claim's description and returns None -- NOT a best guess -- when no worker scores confidently above zero; (2) a per-worker try/except isolation boundary so one worker's exception never loses another worker's already-completed result; (3) a content-verification function that checks a worker's returned result against the actual claim fields it was given (e.g., claim_id, claimant_name), not just that a result object was returned; (4) an idempotent dispatch log keyed on (claim_id, worker) so a retry after a malformed response never re-dispatches the same claim twice; (5) a which_agent_responsible function that walks a (worker, claim_id, verified_ok) trace and returns the first worker whose verification failed. Use only the Python standard library -- no LangGraph, CrewAI, or AutoGen.

Step 3: Review it against this checklist

What a rushed AI-generated coordination layer tends to get wrong
  • A router that always returns a worker. Given "a tree fell on my car during the storm," does the generated router correctly recognize this as ambiguous and return None, or does it silently pick whichever worker happens to score highest by coincidence -- the exact fail-closed-routing gap this chapter's own Section 6 named?
  • Verification that only checks the result's shape, not its content. Does the AI's "verification" function check that a dict with the right KEYS came back, or does it actually compare the VALUES against the original claim -- the difference between catching this chapter's own Porto/Lisbon-style bug and missing it entirely?
  • A retry with no idempotency tracking. Does the generated retry logic check whether a claim was already successfully dispatched before re-dispatching, or does it just retry blindly whenever a response looks malformed -- risking the exact redundant-dispatch cost multiplication this chapter's own Section 13 demonstrated?

Now compare the AI's code against this chapter's own lesson pattern (Sections 6, 11-13) and against solution.py in the exercises folder. Where do they differ? Does the AI's version actually verify claim CONTENT and track dispatch idempotency, or does it stop at "the call didn't crash, so it must have worked"?
