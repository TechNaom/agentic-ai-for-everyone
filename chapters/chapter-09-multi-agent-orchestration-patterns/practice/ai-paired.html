Chapter 9 Practice — Solo → AI-Paired → Critique 15 min

Now Pair With an AI

A ninth scenario, not in the eight above: a team's supervisor agent, "DispatchBot", routes incoming support requests to three workers (the specific company is left unnamed on purpose, the same way Chapter 7's "ClaimBot" and Chapter 8's "QuoteBot" scenarios did). Two real, layered problems were found in the same incident report. First: DispatchBot's router always returns its highest-scoring worker even when that score is 0 -- so a request like "I have a question about my account" (matching no worker's keywords confidently) gets silently routed to whichever worker happens to be listed first, and that worker then produces a plausible-sounding but completely irrelevant reply. Second, in the same incident: DispatchBot's retry logic re-sends a sub-task to a worker any time the worker's response looks malformed, with no check for whether an EARLIER attempt at the same sub-task had already succeeded -- so a single flaky response pattern quietly triples the cost of one customer's request.

Step 1: Diagnose it yourself, first

Before reading further: name the two distinct problems here using this chapter's vocabulary (one is about what a router should return when it has no confident match; the other is about what a retry loop is missing before it re-sends anything) and write your own fix for each. There's no grading here, just your own reasoning to compare against Step 3.

Step 2: Ask an AI assistant

Thought process: this scenario has two layered problems (a missing fail-closed routing check AND a missing idempotency check), so the prompt needs to ask the AI to find both, not just the more obviously dramatic one -- a shallow prompt like "why did DispatchBot misbehave?" invites an answer that fixates on the wrong-worker reply (the one with a visible, embarrassing customer-facing consequence) and never questions whether the retry logic is silently multiplying cost on every flaky response, which has no visible symptom at all unless someone checks the dispatch log.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice and compare its answer against the critique below.
Show a strong version of this prompt 
Here's my supervisor agent DispatchBot's incident report: [paste the scenario above]. Identify EVERY distinct problem in this report, not just the first one you notice -- there are two -- and name each using this chapter's vocabulary (a router that never returns "no confident match," versus a retry loop with no idempotency tracking). Propose a concrete, specific fix for each, including exactly what data structure or check should have existed before this system shipped.

Step 3: Critique what came back

What a complete diagnosis catches
  • Problem 1 (router never returns "no match"): a router that always picks a highest-scorer, even at a zero score, silently misroutes any genuinely ambiguous or off-domain request -- exactly the fail-closed-routing gap this chapter's own Section 6 named. The fix is a hard rule: the router must return None when the best score is zero, and the supervisor must escalate or clarify rather than dispatch on a guess.
  • Problem 2 (retry with no idempotency tracking): this chapter's own Section 13 explicitly demonstrated how a naive retry-on-any-malformed-response policy can double-dispatch the same sub-task, multiplying an entire worker's cost, not just one step's. The fix is a dispatch log keyed on (subtask, worker), checked before every dispatch attempt including retries.
  • A shallow AI answer often catches only Problem 1 (the more visible, customer-facing bug) and misses that Problem 2 is a quiet cost problem with no obvious symptom until someone audits the dispatch log directly.

Compare the AI's answer against your own Step 1 notes and the two-problem breakdown above. Did it catch both? Did it propose the right fix for each -- a fail-closed router change and an idempotent dispatch log -- or did it conflate the two into one vague "add better error handling" suggestion?
