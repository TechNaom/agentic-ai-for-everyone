Chapter 9 Project — Solo → AI-Paired → Critique 25 min

Now Pair With an AI

You already built the project yourself on Ashgrove Municipal Services' CityScout. Now a fourth scenario, Foxglenn Relief Network (a fictional disaster-relief coordination nonprofit) and its supervisor agent AidScout, gets built a second way: by prompting an AI assistant for a supervisor harness, and reviewing what it hands back with the same skepticism you'd bring to a coworker's pull request before trusting its coordination logic.

Step 1: Design it yourself, first

AidScout dispatches incoming relief requests to two workers: ShelterScout (temporary housing needs) and SupplyScout (food/water/medical supply needs). Before reading further, sketch your own design: what should happen when a request mentions BOTH shelter and supplies in the same sentence -- does it get dispatched to one worker, both, or does the router need a different shape entirely? What should happen if the exact same request arrives twice within a few seconds (a duplicate submission, not a retry)? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same thing

Thought process: the prompt needs to state explicitly that a worker's exception must be caught PER WORKER, not by wrapping the whole run in one try/except -- otherwise a rushed AI answer tends to put a single try/except around the entire dispatch loop, which means one worker's crash silently discards every OTHER worker's already-successful result from the same run, exactly the gap this chapter's own Section 11 named.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
Write a Python stdlib-only supervisor harness for AidScout, a supervisor agent dispatching relief requests to two workers: shelterscout (temporary housing) and supplyscout (food/water/medical supplies). I need: (1) a keyword-based route_subtask(subtask) function that returns None -- not a guess -- when no worker scores confidently above zero; (2) a dispatch_isolated(worker_fn, subtask) function that wraps EACH INDIVIDUAL worker call in its own try/except, so that if one request's dispatch to one worker raises, any OTHER already-completed dispatch in the same run is still returned, not discarded; (3) a run_aid_scout_harness(cases) function that walks a list of cases, each with a list of subtasks, tracks an idempotent dispatch set keyed on (subtask, worker) so a duplicate submission is never re-dispatched, and returns a per-case dict with a trace, a success_rate, and the first agent responsible for any failure. Use only the Python standard library -- no LangGraph, CrewAI, or AutoGen.

Step 3: Review it against this checklist

What a rushed AI-generated supervisor harness tends to get wrong
  • One try/except around the whole run instead of per worker. Does the generated harness wrap each individual dispatch call in its own isolation boundary, or does it put a single try/except around the entire loop -- which would lose every other case's or worker's already-successful result the moment ANY ONE dispatch fails?
  • A router that never returns "no match." Given a request that mentions neither shelter nor supplies clearly, does the router correctly return None, or does it silently pick a default worker -- the same fail-closed-routing gap this chapter's own Section 6 named?
  • No idempotency tracking on the dispatch set. Does the harness check a shared dispatched-pairs set BEFORE calling a worker, or does it call the worker every time regardless of whether that exact (subtask, worker) pair was already handled in this run?

Now compare the AI's code against this chapter's own lesson pattern (Sections 6, 11, 13) and against solution.py in the project folder. Where do they differ? Does the AI's version genuinely isolate failures per worker and track dispatch idempotency, or does it stop at "the loop ran without crashing, so it must be fine"?
