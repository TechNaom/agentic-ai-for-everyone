Chapter 8 Practice — Solo → AI-Paired → Critique 15 min

Now Pair With an AI

A ninth scenario, not in the eight above: a team's agent, "QuoteBot", generates pricing quotes for a service request (the specific company is left unnamed on purpose, the same way Chapter 7's "ClaimBot" scenario did). Two real, layered problems were found in the same cost report. First: QuoteBot's dashboard reported "cost cut by 65%" after the team added model routing -- but that number was computed from raw cost-per-run only; nobody rechecked whether the redesign's success rate also dropped, and it turned out roughly a third of QuoteBot's routed-to-cheap-tier lookups were now silently producing slightly wrong quotes that a human had to fix later. Second, in the same rollout: the team's new cache had NO invalidation, and it was applied to a "current promotional discount" lookup that legitimately changes every week -- so after the first week, every quote using that cached value was quietly wrong, with no error or warning anywhere.

Step 1: Diagnose it yourself, first

Before reading further: name the two distinct problems here using this chapter's vocabulary (one is about which metric was checked before calling the change a "win"; the other is about a specific, named limitation this chapter disclosed about caching) and write your own fix for each. There's no grading here, just your own reasoning to compare against Step 3.

Step 2: Ask an AI assistant

Thought process: this scenario has two layered problems (a missing success-rate check AND a caching-staleness bug), so the prompt needs to ask the AI to find both, not just the more obviously dramatic one -- a shallow prompt like "why did QuoteBot's quotes go wrong?" invites an answer that fixates on the cache bug (the one with a visible, dramatic consequence) and never questions whether the reported "65% cheaper" cost number was ever validated against success rate at all.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice and compare its answer against the critique below.
Show a strong version of this prompt 
Here's my agent QuoteBot's cost-control rollout report: [paste the scenario above]. Identify EVERY distinct problem in this report, not just the first one you notice -- there are two -- and name each using this chapter's vocabulary (a raw cost-reduction number reported without a success-rate-aware recheck, versus a cache with no invalidation applied to a value that legitimately changes over time). Propose a concrete, specific fix for each, including exactly what should have been measured or built differently before this rollout shipped.

Step 3: Critique what came back

What a complete diagnosis catches
  • Problem 1 (cost cut reported without a success-rate recheck): a "65% cheaper" headline computed from raw cost-per-run says nothing about whether the routed-to-cheap-tier steps got LESS accurate -- exactly the honest trade-off this chapter's own Section 13 disclosed and then verified with cost_per_success before calling its own result a real win. The fix is a standing rule: no cost-reduction claim ships without a paired success-rate (or cost-per-success) check.
  • Problem 2 (caching with no invalidation on a volatile value): this chapter's own Section 8 explicitly disclosed that its minimal cache never expires and is only safe for genuinely stable lookups -- QuoteBot's promotional-discount value is the exact opposite case. The fix is either a TTL on that specific cache entry or excluding that lookup from caching entirely, not a blanket "add more caching" answer.
  • A shallow AI answer often catches only Problem 2 (the more dramatic, visible bug) and misses that Problem 1 is a process gap -- the team never built the success-rate check at all, not just chose not to look at it this one time.

Compare the AI's answer against your own Step 1 notes and the two-problem breakdown above. Did it catch both? Did it propose the right fix for each -- a standing success-rate-recheck rule, and a cache-staleness fix -- or did it conflate the two into one vague "be more careful with optimizations" suggestion?
