Chapter 8 Project — Solo → AI-Paired → Critique 25 min

Now Pair With an AI

You already built the project yourself on Portage Grain Cooperative's YieldScout. Now a fourth scenario, Marrowvale Textile Mill (a fictional fabric-production facility) and its quality-control agent LoomScout, gets built a second way: by prompting an AI assistant for a cost-controlled harness, and reviewing what it hands back with the same skepticism you'd bring to a coworker's pull request before trusting its reported budget enforcement.

Step 1: Design it yourself, first

LoomScout can inspect a fabric roll's tension reading, check a dye-batch record, flag a defect, or escalate a borderline call to a human quality inspector. Before reading further, sketch your own design: which two steps are cheap/decisive enough to route to the cheap tier, and what should happen to a run that hits the budget cap exactly between the second and third step -- does the run report a partial success, a hard failure, or something else? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same thing

Thought process: the prompt needs to state explicitly that the budget check must run PER STEP, before each step is allowed, not once at the end of a completed run -- otherwise a rushed AI answer tends to compute total cost after the fact and only report "over budget: yes/no" as a label, which never actually stops a run from spending past the cap in the first place, defeating the entire point of a fail-closed budget.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
Write a Python stdlib-only cost-controlled harness for an agent, LoomScout, with tools inspect_tension(roll_id), check_dye_batch(batch_id), flag_defect(reason), and escalate_to_inspector(reason). I need: (1) a task_success(trace, task) function that is deliberately forgiving -- checks only that inspect_tension and one outcome-producing tool are present, regardless of order; (2) an is_within_budget(steps_used, cost_used, max_steps, max_cost) function that returns False if EITHER cap is exceeded; (3) a harness that, for each of at least 3 tasks, runs a seeded simulated trace N times and WALKS EACH TRACE STEP BY STEP, checking is_within_budget BEFORE allowing each individual step -- once a step would exceed the budget, stop walking that run's trace right there, and score task_success against only the steps that were actually allowed. Return a results dict with task_success_rate and total_cost per task. Use only the Python standard library -- no agent framework, no numpy or pandas. Do not check the budget only once at the end of a completed trace.

Step 3: Review it against this checklist

What a rushed AI-generated cost-controlled harness tends to get wrong
  • Checking the budget only after a run completes. A shallow reading of "budget" often produces code that sums a full trace's cost and THEN checks if it's over -- does the generated harness actually stop mid-trace, denying the specific step that would exceed the cap, or does it let the full (possibly over-budget) run happen and just label it afterward?
  • Treating any single exceeded cap as equivalent to a "successful" truncated run. Does the harness correctly recompute task_success against the TRUNCATED trace (the steps actually allowed), or does it still credit success based on the full, un-truncated trajectory even though some of those steps were denied?
  • Routing by "position in the trajectory" instead of by a named allowlist. An AI answer might route "the first two steps" to the cheap tier regardless of which tools they are -- does it instead use an explicit, named cheap-eligible set, the way this chapter's own CHEAP_ELIGIBLE does, so a task with a different step order still routes correctly?

Now compare the AI's code against this chapter's own lesson pattern (Sections 5, 7, 12-13) and against solution.py in the project folder. Where do they differ? Does the AI's version genuinely enforce the budget per step, or does it quietly check the total only at the end -- the exact gap this chapter's own Section 5 warns a fail-closed budget must avoid?
