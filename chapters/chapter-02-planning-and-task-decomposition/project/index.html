Project: Dual-Mode Planning for RouteBot

Cobblestone Courier Co. wants RouteBot to handle two kinds of task with two different planning strategies. Task A (processing a new delivery order — verify address, calculate route, dispatch driver) needs a fixed, up-front plan, since no step's result changes whether a later step is worth running. Task B (diagnosing a delayed delivery) needs emergent, one-step-at-a-time planning, since the right follow-up check — traffic, weather, or a driver check-in — depends entirely on what the delay status notes actually say. Complete the three-TODO scaffold in starter.py so both strategies work correctly, including a fixed plan that can re-plan on failure.

Not one of this course's numbered projects This is a chapter mini-project, not the L1/L2/L3/L4 ladder from docs/curriculum/CURRICULUM_MAP.md (Chapter 2's own material folds into the L2 Assisted project that ships after Chapter 4). It exists so both of this chapter's planning strategies get one combined, hands-on build before that larger project arrives.

The three TODOs

  1. TODO 1 — run_fixed_dispatch(): the fixed-plan executor, with a re-planning guard built in.
  2. TODO 2 — decide_next_delay_check(): the emergent decision function, branching on the delay notes.
  3. TODO 3 — classify_task_planning_mode(): the fixed-vs-emergent decision heuristic itself.
