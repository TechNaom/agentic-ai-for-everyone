Now Pair With an AI

You already worked the exercises yourself on Fenwick Home Repair Co-op's RepairBot. Now a third scenario, Mossgate Dental Group (a fictional dental practice) and its treatment-estimate agent DentalBot, gets built a second way: by prompting an AI assistant for a reflection step, and reviewing what it hands back with the same skepticism you'd bring to a coworker's pull request before it ships to Mossgate's real patients.

Step 1: Design it yourself, first

DentalBot drafts a cost estimate for a procedure (a flat fee per procedure code, e.g. cleaning $120, filling $220, root canal $900) and must also flag any procedure that requires pre-authorization from the patient's insurer before it can be scheduled (currently: root canals and crowns). Before reading further, sketch your own reflect_on_estimate(draft_text, procedure_code, requires_preauth) function: what does it check the draft against, and what does it do when a check fails? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same thing

Thought process: the prompt needs to state BOTH checks explicitly (price correctness AND pre-authorization flagging) and make clear that a draft passing one check can still fail the other — otherwise a rushed AI answer tends to implement only whichever check is mentioned first and treat the function as done.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
Write a Python function reflect_on_estimate(draft_text, procedure_code, actual_price) for a dental office's estimate bot. It should check TWO independent things about draft_text (a natural-language estimate the bot already drafted): (1) does draft_text state a dollar amount, and does it match actual_price exactly -- if not, the draft is wrong and must be corrected; (2) if procedure_code is "root_canal" or "crown" (procedures that require insurer pre-authorization before scheduling), does draft_text actually mention pre-authorization/approval -- if the procedure needs it and the draft doesn't mention it, that's a separate, independent problem, even if the price is correct. The function should return a (revised_text, was_changed) tuple: if both checks pass, return the original draft unchanged; otherwise return a corrected version that fixes whichever check(s) failed, and explain why in a comment. Do not use any agent framework, and do not assume checking one thing means the other is also fine.

Step 3: Review it against this checklist

What a rushed AI-generated reflection function tends to get wrong
  • Only implementing one of the two checks. A shallow reading of the prompt often produces a function that verifies the price but silently ignores the pre-authorization requirement (or vice versa) — does the generated code genuinely check both, independently, or does getting one right make it look done at a glance?
  • Treating "the draft mentions a dollar sign" as equivalent to "the draft states the correct price." A function that only checks whether a price is stated, not whether it's the right one, would have let this chapter's own real BikeBot bug (Section 6's live self-critique call correctly named the gap but its own suggested revision still never actually computed the number) sail straight through — extracting a number is not the same as verifying it.
  • Letting a live model call "confirm" the fix instead of grounding it in an independently computed value. This chapter's own lesson demonstrated a real case where a second model call correctly diagnosed a problem but produced a revision that still didn't fix it — the reliable check is always actual_price, computed in plain Python, not a second round of the model's own judgment.
