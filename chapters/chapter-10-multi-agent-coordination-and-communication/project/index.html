Project: A Peer Coordination Harness for Ravenshollow Talent Agency

This is a chapter mini-project, not one of this course's numbered L1-L4 projects — the L3 Independent project was deferred past Chapter 8, past Chapter 9, and is still not yet built as of this chapter (not built here either; see PROJECT_STATE.md). Scenario: Ravenshollow Talent Agency, a fictional talent-booking agency, wants CastingScout and BookingScout -- two genuine PEER agents, not a supervisor and a worker -- coordinated the same way the lesson's DockScout and YardScout were.

The three pillars, combined
  • Message validation — normalizes safe whitespace padding in a message's keys, but fails closed on a genuinely missing or renamed field.
  • Atomic shared claim-check — a single lock guards both the check and the claim, so two peers can never both succeed on the same gig.
  • Assembled, attributed harness — processes every case's claims, detects and breaks a deadlock, and attributes any duplicate to the specific agent whose claim was rejected.
