Now Pair With an AI

A ninth scenario, not in the eight above: a two-peer negotiation system, "NegotiatorBot" (the specific company is left unnamed on purpose, the same way Chapter 9's "DispatchBot" scenario did), where a buyer-side agent and a seller-side agent exchange messages to agree on a shipping rate. Two real, layered problems were found in the same incident report. First: neither agent checks a SHARED record of already-agreed rates before proposing one, so both agents independently proposed and "locked in" conflicting rates for the same shipment on the same day -- no shared state, no lock, no single source of truth. Second, in the same incident: when the two agents' proposals didn't match, both were configured to wait for the OTHER to send a revised offer first -- and neither ever did, so the negotiation simply stalled with no error, no timeout, and no alert.

Step 1: Diagnose it yourself, first

Before reading further: name the two distinct problems here using this chapter's vocabulary (one is about what's missing before either agent commits to a rate; the other is about what's missing once the two agents disagree) and write your own fix for each. There's no grading here, just your own reasoning to compare against Step 3.

Step 2: Ask an AI assistant

Thought process: this scenario has two layered problems (a missing shared claim-check AND a missing deadlock timeout), so the prompt needs to ask the AI to find both, not just the more obviously dramatic one -- a shallow prompt like "why did the negotiation fail?" invites an answer that fixates on the conflicting-rates bug (the one with a visible, costly consequence) and never questions whether the stalled negotiation has any detection mechanism at all, which has no visible symptom unless someone notices the negotiation never actually closed.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice and compare its answer against the critique below.
Show a strong version of this prompt 
Here's my two-peer negotiation system's incident report: [paste the scenario above]. Identify EVERY distinct problem in this report, not just the first one you notice -- there are two -- and name each using this chapter's vocabulary (duplicated work from a missing shared claim-check, versus a deadlock with no timeout). Propose a concrete, specific fix for each, including exactly what shared state, lock, or timeout mechanism should have existed before this system shipped.

Step 3: Critique what came back

What a complete diagnosis catches
  • Problem 1 (no shared claim-check before committing a rate): two peers each reasoning correctly about their own half of the negotiation still converged on conflicting committed rates with nothing forcing either one to check a SHARED record first -- exactly the duplicated-work gap this chapter's own Section 8 demonstrated live. The fix is a locked, atomic check-and-commit against shared state, the same discipline Section 9's coordinated_claim used.
  • Problem 2 (no deadlock timeout): this chapter's own Section 13 explicitly constructed how two agents each waiting for the other to move first can stall forever with zero error signal. The fix is a timeout keyed on elapsed waiting time, plus a pre-agreed tie-breaker (Section 14) that lets ONE agent act without needing the other's permission.
  • A shallow AI answer often catches only Problem 1 (the more visible, costly bug) and misses that Problem 2 means the system has NO mechanism at all for detecting a stalled negotiation, which is arguably the more dangerous gap since it fails completely silently.

Compare the AI's answer against your own Step 1 notes and the two-problem breakdown above. Did it catch both? Did it propose the right fix for each -- a locked shared claim-check and a deadlock timeout with a pre-agreed tie-breaker -- or did it conflate the two into one vague "add better coordination" suggestion?
