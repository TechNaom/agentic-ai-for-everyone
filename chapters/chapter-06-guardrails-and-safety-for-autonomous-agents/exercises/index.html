Chapter 6 Exercises ~40 min, hands-on

Exercises: Guardrails and Safety for Autonomous Agents

These exercises use a second scenario, deliberately different from the lesson's Millbrook Credit Union/LedgerBot hook: Amberlock Self-Storage, a fictional self-storage facility. Its operations agent, DispatchBot, can check a unit's status, issue a refund, remotely unlock a unit (a physical security override), and run a facility "reconciliation script." Applying this chapter's guardrail concepts to a fresh scenario is the point.

Exercise standard Eight tasks total, worth 19 points. Five are marked production-gear — a real tool allowlist check, a real approval-threshold check, a real dispatch_action composition, diagnosing a real "system-prompt-only guardrail" trace, and a real fail-safe default-deny wrapper, not just concept recall.

Tasks

  1. Map facts to guardrail concepts — assign tool allowlist, human-approval checkpoint, sandboxed tool execution, action budget, or fail-safe default deny to five DispatchBot facts.
  2. Dependency reasoning — does an approval check that fails open instead of fails safe make an unapproved action more or less likely to execute?
  3. (Production-gear) Tool allowlist check — refuse a tool name never actually given to the agent.
  4. (Production-gear) Approval-threshold check — decide which actions require human approval.
  5. (Production-gear) dispatch_action composition — combine allowlist, sandbox, and approval checks, failing safe throughout.
  6. (Production-gear) Failure diagnosis — correctly name a "system-prompt-only guardrail" from a trace.
  7. (Production-gear) Fail-safe default deny — treat an approval error as "not approved."
  8. Completeness check — confirm all five guardrail concepts were actually used.

Full instructions and the scoring rubric are in README.md alongside starter.py (fill in the TODOs) and solution.py (the reference, scores 19/19).
