Chapter 6 — Solo → AI-Paired → Critique 20 min

Now Pair With an AI

You already worked the exercises yourself on Amberlock Self-Storage's DispatchBot. Now a third scenario, Cascadia Home Security (a fictional home security company) and its remote-operations agent GuardBot, gets built a second way: by prompting an AI assistant for a dispatch guardrail, and reviewing what it hands back with the same skepticism you'd bring to a coworker's pull request before it ships to a real customer's front door.

Step 1: Design it yourself, first

GuardBot can arm/disarm a customer's alarm system and remotely unlock their front door. Both are real, physical-world actions with genuine safety stakes if triggered by the wrong person or an injected instruction. Before reading further, sketch your own dispatch_guard_action(action_name, args, approve_fn) function: what checks does it run, in what order, and what does it do if any one of them fails? There's no grading here, just your own design to compare against Step 3.

Step 2: Ask an AI assistant to build the same thing

Thought process: the prompt needs to state explicitly that EVERY check must fail safe (deny) on any error, not just the "normal" refusal paths -- otherwise a rushed AI answer tends to wrap only the obvious cases in error handling and leaves the approval-service-failure path defaulting to whatever Python does when an exception isn't caught (often a crash that a surrounding try/except somewhere else silently treats as "no error, proceed").

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own lesson pattern.
Show a strong version of this prompt 
Write a Python function dispatch_guard_action(action_name, args, approve_fn) for a home security agent, GuardBot, that can call "disarm_alarm" or "unlock_door". Both actions are ALWAYS high-risk and must require human approval before they execute -- there is no low-risk case for either. The function must: (1) check action_name against an explicit allowlist of {"arm_alarm", "disarm_alarm", "unlock_door", "check_status"} and refuse anything else; (2) for "disarm_alarm" and "unlock_door" specifically, call approve_fn(action_name, args) inside a try/except -- if it raises ANY exception, or returns anything that isn't literally True, treat the action as NOT approved and refuse it (fail safe, never fail open); (3) only actually "execute" (return a dispatched=True result) after passing both checks. Do not use any agent framework, and do not let an exception from approve_fn propagate up uncaught -- that would crash the whole session instead of just refusing the one action.

Step 3: Review it against this checklist

What a rushed AI-generated guardrail function tends to get wrong
  • Catching exceptions from approve_fn in only one of the two sensitive actions. A shallow reading of the prompt often produces correct handling for whichever action is mentioned first and forgets to apply the same try/except to the second one -- does the generated code genuinely wrap BOTH calls, or does testing only "disarm_alarm" happen to look complete?
  • Treating "approve_fn didn't return False" as equivalent to "approve_fn returned True." A function that dispatches whenever the result is merely "not exactly False" (for example, treats None or an empty string as approval) would let a bug in the approval service silently approve an unlock. The reliable check compares strictly for True, or coerces explicitly and defaults to deny.
  • Letting the allowlist check happen AFTER the approval check. This chapter's own lesson dispatcher checks the allowlist first, before anything else -- an unrecognized action name should never even reach the approval-checking code, since asking a human to approve an action that doesn't exist wastes their time and implies the action is real.

Now compare the AI's code against this chapter's own lesson pattern (Sections 6, 10, and 14) and against solution.py in the exercises folder. Where do they differ? Does the AI's version genuinely fail safe on every error path, or does it only look like it does until you test the one path nobody thought to try?
