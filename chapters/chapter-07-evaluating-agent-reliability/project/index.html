Project: An Eval Harness for TriageScout

Emberlyn Underwriting wants TriageScout evaluated the same way this chapter's own FactScout was: combine task success (a forgiving, order-independent check on whether the right kind of outcome was reached), trajectory correctness (a strict, order-sensitive check against a ground-truth expected sequence), and non-determinism (a harness that runs each task 20 times and returns the raw per-run results so pass@k can be computed) into one real, reusable eval harness. Complete the three-TODO scaffold in starter.py so all three pillars work correctly and compose into one working harness.

It exists so this chapter's three eval pillars get one combined, hands-on build before that larger project arrives.
