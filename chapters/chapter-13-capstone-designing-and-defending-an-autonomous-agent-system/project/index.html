L4 Architecture Challenge (the capstone — this course's FINAL project) ~120 min, independent, no scaffold

Project: Thornwick Marketplace Collective — the L4 Architecture Challenge

This IS Chapter 13's whole deliverable — not a chapter mini-project alongside a separate lesson. L4's own definition: "design and defend a complete multi-component autonomous agent system; business/system problem only." There is deliberately no starter.py — L4, like L3 before it, hands you a problem statement, not a fill-in-the-blank file.

The problem, in short

Thornwick Marketplace Collective, a fictional artisan marketplace, has three coordinating components: a conversational Buyer Concierge (with a persisted allergy preference), an overnight Maker Fulfillment batch, and a Fraud & Dispute Review process gating refunds behind human approval. Buyer Concierge and Maker Fulfillment both read/write the SAME shared inventory ledger and can race each other for the same sku's last unit — Chapter 10's coordination problem, not just Chapter 9's dispatch problem.

What the reference solution proves, end to end

  1. Characterizes the problem as multi-agent, naming the specific subtask-independence fact.
  2. Selects ALL EIGHT of Chapters 4-11's mechanisms as load-bearing — the full inventory.
  3. States a reliability/cost budget (95% minimum task-success, 8-cent maximum cost per run).
  4. Implements a real MemoryStore, a locked InventoryLedger.try_claim claim-check, a fail-closed apply_refund guardrail, an idempotent commit_once commit layer, and a grounded grounded_reflect check.
  5. Instruments all three task types with a deterministic harness, including a real claim-check race proving no overselling, and measures real numbers against the stated budget.
  6. Assembles the Architecture Decision Record, naming three rejected alternatives.

Files

  • solution.py — the reference deliverable, no scaffold; scores 14/14.
  • ai-paired.html — a solo-build-then-critique exercise using a second, unnamed marketplace.
