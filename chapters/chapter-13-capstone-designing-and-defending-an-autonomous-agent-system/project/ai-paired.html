Chapter 13 Project — Solo → AI-Paired → Critique 30 min

Now Pair With an AI

You already worked through the L4 Architecture Challenge yourself on Thornwick Marketplace Collective. Now a second, unnamed regional artisan marketplace (left generic, matching this course's own convention for quick AI-paired variants) gets a full capstone-shaped deliverable — characterization, mechanism selection, budget, implementation, and instrumentation — built a second way: by prompting an AI assistant for the whole thing, and reviewing what it hands back with the same skepticism a design-review panel would bring to a capstone defense.

Step 1: Design and instrument it yourself, first

The second marketplace runs the same three-component shape: a conversational buyer agent whose stated dietary preference must persist across separate orders, an overnight seller-fulfillment batch sharing ONE stock ledger with the buyer agent, and a dispute-review step gating refunds above a dollar threshold behind human approval, with the written resolution explanation as free text. Before reading further: characterize this problem yourself, select all eight mechanisms, state a budget, and sketch how you'd implement and PROVE the shared-ledger claim-check prevents overselling. There's no grading here — compare your own attempt against Step 3's checklist and against this chapter's own solution.py.

Step 2: Ask an AI assistant to build the same deliverable

Thought process: an L4-shaped prompt has to force the AI through all five framework steps for a MULTI-component system, demand it name BOTH justifications for multi-agent where both apply, and demand a real, executed proof that the shared-resource race is actually prevented — not just a design narrative that asserts safety.

Write the prompt you'd give an AI assistant:

Paste your prompt into your assistant of choice, save its response separately, and compare it against the checklist below before looking at this chapter's own project pattern.
Show a strong version of this prompt 
I need a complete multi-component agent architecture AND a working reference implementation for a second artisan marketplace: a conversational buyer agent (a dietary preference stated once must inform every LATER order), an overnight seller-fulfillment batch sharing ONE stock ledger with the buyer agent, and a dispute-review step (refunds above a threshold need human approval; the written resolution is free text). Do all of the following, in order: (1) characterize multi-agent need, naming BOTH possible justifying facts and which apply; (2) for each of memory, reflection, guardrails, reliability measurement, cost control, multi-agent dispatch, peer communication, and the operating layer, state whether it's load-bearing and why; (3) state a reliability/cost budget; (4) implement a LOCKED claim-check (not an unlocked read-then-write) for the shared stock ledger, a fail-CLOSED refund guardrail, an idempotent overnight commit, and a grounded check on the dispute explanation text; (5) write a harness that actually races two concurrent claims on the same last unit and PROVES only one wins, plus measures real success-rate and cost-per-success against the budget -- don't just assert the numbers.

Step 3: Review it against this checklist

What a rushed AI-generated L4 submission tends to get wrong
  • An unlocked stock check instead of a claim-check. Does the inventory code LOCK the sku before checking stock, or does it "check, then decrement" unlocked -- which oversells the moment two components race it for real, exactly the gap Chapter 10's own claim-check closes?
  • Only one of the two multi-agent justifications named. Does the response name BOTH the subtask-independence fact (Ch9) AND the shared-state-concurrency fact (Ch10), or stop after the first one it happens to find?
  • Reflection claimed but not grounded. Does the dispute-text check actually verify specific required facts are present, or just re-ask the model to "review this" with no concrete criterion?
  • A budget asserted, not measured, or a harness that never actually races the claim-check. Does the harness run two concurrent claims on the SAME last unit and print which one won, or just claim the design "prevents overselling" with nothing that could prove or disprove it?
